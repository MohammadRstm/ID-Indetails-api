# Content storage

Private object storage for the client portal's content. The files themselves never pass through the API: the browser uploads each part of a file straight to the store on a short-lived signed link, and reads the file back through another. The API only starts, lists, completes and deletes uploads, and hands out a link after it has checked who is asking. Object keys are generated by the server and never contain a file name.

Code: `Services/ContentStore/` (`IContentStore` and its three implementations), `Extensions/ContentStoreServiceCollectionExtensions.cs`, `Controllers/LocalContentStoreController.cs`.

## Providers

`ContentStore:Provider` picks one:

| Provider | For | What it is |
|---|---|---|
| `None` (default) | A server with nothing set up yet | `UnconfiguredContentStore`. The app runs; anything that needs the store answers `503 content_storage_unavailable` ("Client portal file storage isn't set up yet…"). `IContentStore.IsAvailable` is false |
| `Local` | Development and tests | `LocalContentStore`. A folder on disk. Only Development, Testing and Seeding may use it; any other environment (Production, Staging) refuses to start with it. Because there is no S3 to presign for it, it hands out its own signed links, served by `LocalContentStoreController` |
| `R2` | Production | `R2ContentStore`. A private Cloudflare R2 bucket through its S3 API (AWSSDK.S3). A network failure or a 5xx answer from R2 becomes `503 content_storage_unavailable` ("The file storage can't be reached right now…"); `R2ContentStore` logs the cause as a warning, with the exception, before the 503 is answered |

### The local store

- Objects are at `{RootPath}/{key}`. An upload in progress is at `{RootPath}/.uploads/{uploadId}/`, with a `meta.json` (the key and content type) and one `{partNumber}.part` file per part. Completing joins the parts into the object and deletes that folder.
- Its links are relative: `/api/content-store/parts/{token}` (PUT the raw bytes of a part) and `/api/content-store/objects/{token}` (GET, with range support). A token is `base64url(payload).base64url(HMAC-SHA256(payload))`; the payload says what it allows (a part upload or a download, the key, the expiry in Unix seconds). A link made for one operation is refused for the other, and a changed, expired or foreign token answers `404` with no detail. A part larger than 5 GiB is refused, as on R2.
- The controller is anonymous and exempt from the rate limits, because the signed token is the authorization (like a presigned URL) and its requests carry no sign-in. It answers `404` unless the local store is the one in use.
- A download is served with `X-Content-Type-Options: nosniff`, `Cache-Control: private, max-age={seconds the link has left}` and `Content-Disposition` `inline` or `attachment`.
- Completing an upload whose folder is gone (joined by another attempt a moment ago, or aborted) does nothing, as on R2 (below).

## Configuration

| Key | Default | What |
|---|---|---|
| `ContentStore:Provider` | `None` | `None`, `Local` or `R2`. `appsettings.Development.json` sets `Local`; the production compose file sets `R2` |
| `ContentStore:R2:AccountId` | none | The Cloudflare account id. Required for `R2` |
| `ContentStore:R2:Bucket` | none | The bucket's name. Required for `R2` |
| `ContentStore:R2:AccessKeyId` | none | The R2 API token's access key id. Required for `R2` |
| `ContentStore:R2:SecretAccessKey` | none | **Secret.** The R2 API token's secret. Required for `R2` |
| `ContentStore:R2:Endpoint` | `https://{AccountId}.r2.cloudflarestorage.com` | Only to override the S3 endpoint; it must be https. Signed links work on that endpoint only, not on a custom domain |
| `ContentStore:Local:RootPath` | `App_Data/portal-content` | A folder, relative to the content root unless absolute. Gitignored. Never a folder the web server serves |
| `ContentStore:Local:SigningKey` | random per start | Signs the local store's links. Empty, a random 32-byte key is made each time the API starts, so links stop working on restart. Set one only to keep links across restarts |

The API refuses to start when the provider is `R2` and any of the four R2 values is empty (the message names the missing key), when the endpoint isn't https, and outside Development, Testing and Seeding when the provider is `Local`.

### Where to set them

- **Production.** The server's `.env` holds `R2_ACCOUNT_ID`, `R2_BUCKET`, `R2_ACCESS_KEY_ID` and `R2_SECRET_ACCESS_KEY` (template: `deploy/.env.production.example`). `deploy/docker-compose.prod.yml` passes them to the API as `ContentStore__Provider` (fixed to `R2`) and `ContentStore__R2__AccountId`, `…__Bucket`, `…__AccessKeyId`, `…__SecretAccessKey`. All four are required by the compose file: the stack doesn't start without them. A change takes effect at the next deployment or API restart.
- **Development.** `Local` needs nothing: it is the default in `appsettings.Development.json` and writes to `App_Data/portal-content`. To try R2 from your machine, put its values in user secrets (never in a committed file):

  ```bat
  dotnet user-secrets set "ContentStore:Provider" "R2" --project ID-Indetails.api
  dotnet user-secrets set "ContentStore:R2:AccountId" "<account id>" --project ID-Indetails.api
  dotnet user-secrets set "ContentStore:R2:Bucket" "<bucket>" --project ID-Indetails.api
  dotnet user-secrets set "ContentStore:R2:AccessKeyId" "<access key id>" --project ID-Indetails.api
  dotnet user-secrets set "ContentStore:R2:SecretAccessKey" "<secret access key>" --project ID-Indetails.api
  ```

  Browser uploads to R2 also need the bucket's CORS rule to list `http://localhost:5173`, and the client dev server's Content-Security-Policy, if it sets one, to allow the R2 origin.
- **Tests.** `ApiFactory` sets `ContentStore:Provider` to `Local` with a temporary folder per factory, deleted with it.

## Cloudflare setup (once)

1. **Create a bucket** in R2 (Cloudflare dashboard → R2 → Create bucket). Keep it **private**: leave the `r2.dev` public URL disabled and don't attach a custom domain. Files are only ever read through the API's signed links.
2. **Create an R2 API token** (R2 → Manage R2 API tokens) with **Object Read & Write**, limited to **that bucket** only. Copy the access key id and secret access key (the secret is shown once) and the account id into the server's `.env` as `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY` and `R2_ACCOUNT_ID`; the bucket's name is `R2_BUCKET`.
3. **Add a CORS rule** to the bucket (Settings → CORS policy), so the browser may PUT parts and GET files from the app's origin. `AllowedOrigins` is the app's https origin, exactly as visitors type it (`https://<PUBLIC_DOMAIN>`, no trailing slash):

   ```json
   [
     {
       "AllowedOrigins": ["https://app.example.com"],
       "AllowedMethods": ["PUT", "GET", "HEAD"],
       "AllowedHeaders": ["content-type"],
       "MaxAgeSeconds": 3600
     }
   ]
   ```

   `ETag` doesn't need to be exposed: the server lists the uploaded parts itself when it completes an upload, and never trusts the browser's list.
4. **Set the four `R2_*` variables** in the server's `.env` (docs/server-setup.md), then deploy.

### The client's Content-Security-Policy

The browser talks to R2 only if the client's Content-Security-Policy allows it. The compose file passes `CONTENT_STORE_ORIGIN` (`https://{R2_ACCOUNT_ID}.r2.cloudflarestorage.com`) to the `web` container, and the client's nginx adds it to its Content-Security-Policy, so the browser may upload to and preview from R2. There is nothing to set by hand: it follows `R2_ACCOUNT_ID`.

## R2 limits that shape the uploads

- A part is 5 MiB to 5 GiB; every part except the last must be the same size; an upload has at most 10,000 parts.
- A presigned link lasts at most 7 days, and works only on the S3 endpoint (`https://{AccountId}.r2.cloudflarestorage.com`), not on a custom domain.
- R2 aborts a multipart upload that was never completed after 7 days by default, and frees its parts, so an abandoned upload doesn't cost storage for long.
- A download link asks R2 to answer with `Cache-Control: private, max-age={seconds the link had left when it was made}`, so the browser never keeps a file much longer than its link lasts.
- Completing an upload R2 no longer has (`NoSuchUpload`: joined by another attempt a moment ago, or abandoned) isn't an error: whether the object exists then decides.
- Links are signed without checksum parameters (`RequestChecksumCalculation` and `ResponseChecksumValidation` are `WHEN_REQUIRED`), because AWSSDK 4 would otherwise add some that R2 and a browser's plain PUT can't satisfy.

## Backups

**R2 content is not in the nightly server backup.** `backup.sh` dumps the database and tars the `files` volume (photos and videos); it never reads the bucket. A deleted object is gone. If the portal's files must survive an accident, copy the bucket elsewhere on a schedule (for example `rclone sync` with an R2 token that can only read it).

The `Local` store's folder is for development only and isn't backed up either.
